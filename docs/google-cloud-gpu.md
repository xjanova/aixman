# เช่า GPU จาก Google Cloud (Compute Engine) — วิธีเอาคีย์และตั้งค่า

ผู้ให้เช่า `gce` ใน Admin → GPU ที่เช่า ทำงานแบบเดียวกับ Verda คือเช่า VM ที่มี GPU
บูต container ของเรา แล้วเชื่อมกลับผ่าน tunnel ของเราเอง คิดเงินตามวินาทีที่เครื่องเปิด (ขั้นต่ำ 1 นาที)

> **ไม่ใช่ Colab.** Colab / Colab Pro / Pro+ ไม่มี API ให้สร้างเครื่อง และเงื่อนไขห้ามเอาไปให้บริการคนอื่น
> (ข้อนี้ใช้กับทุกแพ็กเกจ) จึงต่อกับระบบนี้ไม่ได้ ถ้าคุณมี Colab Pro อยู่ ให้เอาไว้ทดลองโมเดลหรือเทรน LoRA ผ่านหน้า notebook

## การ์ดที่ระบบเช่าได้

| การ์ด | Machine type | VRAM | ราคาปกติ/ชม. | Spot/ชม. (ประมาณ) |
|---|---|---|---|---|
| T4 | n1-standard-8 + T4 | 16 GB | ~$0.73 | ~$0.27 |
| L4 | g2-standard-8 | 24 GB | ~$0.86 | ~$0.35 |
| A100 40GB | a2-highgpu-1g | 40 GB | ~$3.68 | ~$1.48 |
| A100 80GB | a2-ultragpu-1g | 80 GB | ~$5.07 | ~$2.10 |
| H100 80GB | a3-highgpu-1g | 80 GB | ขายเฉพาะ Spot | ~$3.20 |

ราคาในตารางเป็นราคา us-central1 ที่ฝังไว้ในโค้ด (`GCE_SHAPES` ใน `src/lib/gpu/gce.ts`) ภูมิภาคนอกสหรัฐฯ ระบบบวกเพิ่ม 25% เพื่อให้ประเมินเผื่อไว้ก่อน
ยอดจริงดูที่ Cloud Billing เสมอ
**Spot** ถูกกว่า 60–90% แต่ Google ดึงเครื่องคืนได้ทุกเมื่อ เมื่อโดนดึงคืน เครื่องจะลบตัวเองทิ้ง และระบบจะส่งงานไปเครื่องอื่นให้เอง

## ขั้นตอนเอาคีย์ (ครั้งเดียว)

1. **สร้างโปรเจกต์** — https://console.cloud.google.com → แถบบน "Select a project" → **New project** ตั้งชื่อเช่น `aixman-gpu`
2. **ผูกบัญชีเรียกเก็บเงิน** — เมนู **Billing** → Link a billing account (ต้องเป็นบัญชีที่เสียเงินแล้ว บัญชีทดลองฟรีขอโควตา GPU ไม่ได้)
3. **เปิด Compute Engine API** — **APIs & Services → Library** → ค้นหา "Compute Engine API" → **Enable** (รอ 1–2 นาที)
4. **ตรวจว่ามี network `default`** — **VPC network → VPC networks** ต้องมีรายการชื่อ `default` (โปรเจกต์ใหม่มีให้อยู่แล้ว ถ้าลบทิ้งไป เครื่องจะสร้างไม่ได้)
5. **สร้าง Service Account** — **IAM & Admin → Service Accounts → Create service account**
   - ชื่อ: `aixman-renter`
   - Role: **Compute Instance Admin (v1)** และ **Service Account User**
   - กด Done
6. **สร้างคีย์ JSON** — คลิก service account ที่เพิ่งสร้าง → แท็บ **Keys** → **Add key → Create new key → JSON → Create**
   จะได้ไฟล์ `.json` ลงเครื่อง **ไฟล์นี้คือคีย์** เก็บให้ดี อย่า commit ลง git และอย่าส่งในแชต
7. **ขอโควตา GPU** (ขั้นที่คนติดมากที่สุด) — **IAM & Admin → Quotas & System Limits**
   - ค้นหา `GPUS_ALL_REGIONS` → เลือก → **Edit** → ขอเป็น `2` (หรือเท่าจำนวนเครื่องสูงสุดที่ตั้งใน `gpu_max_concurrent_workers`)
   - ค้นหาโควตาของการ์ดในภูมิภาคที่จะใช้ เช่น `NVIDIA_L4_GPUS` ภูมิภาค `us-central1` → ขอ `2`
   - ถ้าจะใช้ Spot ให้ขอ `PREEMPTIBLE_NVIDIA_L4_GPUS` ด้วย (ถ้าไม่มี Spot จะใช้โควตาปกติแทน)
   - ใส่เหตุผลสั้นๆ เช่น "AI image/video rendering for our web service" ปกติอนุมัติภายในไม่กี่ชั่วโมงถึง 2 วัน
8. **ตั้งงบเตือนฝั่ง Google** (แนะนำ) — **Billing → Budgets & alerts → Create budget** เช่น $50/เดือน ให้ส่งอีเมลเตือนที่ 50/90/100%
   ระบบเราคุมด้วย `gpu_daily_budget_usd` อยู่แล้ว แต่ Google ไม่มียอดเงินคงเหลือให้อ่าน การตั้งงบเตือนไว้อีกชั้นจึงปลอดภัยกว่า

## เชื่อมต่อใน aixman

1. Admin → **GPU ที่เช่า** → แท็บผู้ให้เช่า → การ์ด **Google Cloud**
2. เปิดไฟล์ `.json` ด้วย Notepad → คัดลอก**ทั้งไฟล์** → วางในช่อง → **เชื่อมต่อ**
   - ระบบตรวจคีย์กับ Google ก่อนบันทึก และเข้ารหัสเก็บ
   - ถ้ายังไม่ได้รับโควตา จะขึ้นคำเตือน "ยังไม่มีโควตา GPU" ซึ่งบันทึกคีย์ได้ตามปกติ พอโควตาอนุมัติ ระบบจะเริ่มเช่าได้เอง
3. กด **ทดสอบการเชื่อมต่อ (ไม่เสียเงิน)** — ต้องเห็นจำนวนเครื่องที่หาได้ต่อโมเดล
4. กด **เช่าเครื่องทดสอบ** หนึ่งครั้ง (เสียเงินจริง) แล้วสั่งงานจากสตูดิโอ เพื่อยืนยันว่าบูตและเรนเดอร์ได้ครบวงจร
   VM ใช้เวลาบูตราว 4–6 นาที (เปิดเครื่อง, ตรวจ driver, ดึง image)

## ถ้ามีปัญหา

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| "ใช้ข้อมูลนี้เชื่อมต่อ Google Cloud ไม่ได้" | ยังไม่เปิด Compute Engine API, คัดลอก JSON ไม่ครบ หรือ service account ไม่มี role ตามขั้นที่ 5 |
| ทดสอบแล้วได้ 0 เครื่อง | ยังไม่มีโควตา (ขั้นที่ 7) หรือ VRAM ของการ์ดที่มีโควตาไม่พอสำหรับโมเดลนั้น (เช่น T4 16 GB รันได้แค่โมเดลเล็ก) |
| เช่าแล้วขึ้น `ZONE_RESOURCE_POOL_EXHAUSTED` | โซนนั้นการ์ดหมดชั่วคราว ระบบจะลองโซนถัดไปเอง ขอโควตาไว้หลายภูมิภาคจะช่วยได้ |
| เครื่องไม่พร้อมสักที | ดู log ของเครื่องในตารางเครื่อง (ระบบอ่านจาก serial console ของ VM) |
| คีย์หลุด | IAM & Admin → Service Accounts → Keys → ลบคีย์นั้นทันที แล้วสร้างใหม่และวางในหน้า Admin |

## ตัวป้องกันค่าใช้จ่ายที่มีในระบบ

- ทุก VM มี `maxRunDuration` 12 ชั่วโมง: **Google จะลบเครื่องเอง** แม้ว่า cron ของเราจะหยุดทำงาน
- ดิสก์ถูกสร้างแบบ `autoDelete` จึงถูกลบไปพร้อมเครื่อง ไม่ค้างบิล
- เครื่องที่ถูกหยุดหรือ suspend (ซึ่งยังคิดค่าดิสก์) ระบบจะถือว่าเสีย แล้วลบทิ้ง
- เครื่องชื่อ `aixman-…` ที่ไม่มีใน DB จะถูกตัวกวาดเครื่องตกค้างลบ (orphan sweep)
